# CHANGELOG

All notable changes to the **Oryxus Brand Engine** will be documented in this file.

This project follows **Semantic Versioning (SemVer)** and maintains a complete history of architectural, methodological, and documentation changes.

---

# Versioning Policy

The project follows the format:

```
MAJOR.MINOR.PATCH
```

| Component | Meaning |
|-----------|---------|
| MAJOR | Breaking changes or significant methodology revisions |
| MINOR | New systems, frameworks, or major documentation additions |
| PATCH | Improvements, corrections, formatting, clarifications, and non-breaking updates |

Example:

```
v2.3.4

Major = 2
Minor = 3
Patch = 4
```

# Change Categories

Every repository change should fall into one or more of the following categories.

### Added

New systems, documentation, frameworks, or assets.

### Changed

Improvements to existing methodology.

### Deprecated

Features scheduled for removal.

### Removed

Content intentionally removed from the repository.

### Fixed

Corrections without changing methodology.

### Security

Changes affecting confidentiality, repository governance, or operational security.

---

# Documentation Policy

Every significant change must:

- Update the relevant document version.
- Update this changelog.
- Preserve historical records.
- Avoid rewriting history.

The changelog is append-only.

Historical entries should never be deleted.
