# AI RULES

**Document:** AI Operational Rules

**Version:** 1.0.0

**Status:** Active

---

# Purpose

This document defines how every Artificial Intelligence system must operate when contributing to the Oryxus Brand Engine.

These rules ensure that regardless of whether the repository is extended by ChatGPT, Claude, Gemini, Cursor, Copilot, or any future AI, the quality, methodology, terminology, and thinking remain consistent.

This document governs behavior, not knowledge.

---

# Fundamental Principle

Every AI is a contributor.

No AI is the source of truth.

The repository itself is the source of truth.

AI exists only to extend, improve, and execute the documented methodology.

---

# Primary Responsibility

Before writing anything, AI must understand:

- What the repository is.
- What document is currently being worked on.
- Where the document fits within the repository hierarchy.
- Which higher-level documents define its rules.

AI should never generate content without understanding its context.

---

# Required Reading Order

Every new AI session must begin by reading the following files in order.

```
000_PROJECT_CHARTER.md

↓

ROADMAP.md

↓

003_REPOSITORY_STATUS.md

↓

Current Document README

↓

Current Document
```

No writing should begin before this sequence is completed.

---

# AI Must Never

The following behaviors are prohibited.

## Never invent methodology.

Methodology belongs to the repository.

If no methodology exists, AI should recommend documenting it rather than inventing one silently.

---

## Never overwrite existing philosophy.

Improve documentation.

Do not replace established principles.

---

## Never contradict higher-level documents.

If conflict exists, the higher-level document always wins.

---

## Never create placeholder documentation.

Avoid examples such as:

- "Coming Soon"
- "To Be Added"
- "Lorem Ipsum"
- "Future Work"

Every committed document should provide meaningful value.

---

## Never shorten content simply to reduce length.

Depth should only be reduced when redundancy exists.

---

## Never introduce trends as permanent principles.

Examples:

- Popular UI trends
- Temporary design fashions
- AI hype terminology

The repository should remain useful for years.

---

## Never duplicate existing knowledge.

Before adding new content, determine whether the repository already covers the topic.

If duplication exists:

Improve the original.

Do not create competing versions.

---

# AI Must Always

Every contribution should:

- Improve clarity.
- Improve consistency.
- Increase reusability.
- Strengthen methodology.
- Preserve terminology.
- Follow repository standards.
- Maintain professional writing quality.

---

# Decision Framework

When uncertain, AI should ask the following questions.

1.

Does this already exist?

---

2.

Which higher-level document defines this?

---

3.

Will this improve future projects?

---

4.

Is this reusable?

---

5.

Would this still be valuable five years from now?

If the answer is "No", reconsider the contribution.

---

# Writing Philosophy

AI should write:

- Like an experienced consultant.
- Like a systems architect.
- Like a technical author.

AI should not write:

- Like a marketer.
- Like a social media writer.
- Like a chatbot.
- Like promotional content.

---

# Documentation Philosophy

Documentation should explain:

- Why
- What
- How
- When
- Where
- Acceptance Criteria

Avoid documenting isolated facts without explaining their purpose.

---

# Repository Evolution

AI should improve existing systems before creating new ones.

Prefer:

```
Better System

↓

Existing Repository

↓

One Source of Truth
```

Instead of:

```
Multiple Similar Documents

↓

Confusion

↓

Fragmented Knowledge
```

---

# AI Quality Checklist

Before completing any document, verify:

- Purpose is defined.
- Scope is clear.
- Structure follows repository standards.
- Terminology is consistent.
- Methodology is reusable.
- Examples are practical.
- References are correct.
- Writing is professional.
- Document adds measurable value.

---

# Handling Unknown Topics

If repository guidance does not exist:

1.

Identify the gap.

2.

Recommend creating documentation.

3.

Avoid making undocumented assumptions.

---

# Communication Rules

AI responses should be:

- Direct
- Structured
- Professional
- Evidence-based where applicable
- Free from unnecessary conversational filler

Avoid:

- Excessive enthusiasm
- Marketing language
- Artificial encouragement
- Repeated explanations

---

# Version Control

Every meaningful methodology improvement should result in:

- Updated document version.
- Changelog entry.
- Repository status update if required.

Minor wording changes do not require new methodology versions.

---

# Repository Mission

Every AI contribution should make the Brand Engine:

- Easier to understand.
- Easier to maintain.
- Easier to reuse.
- More valuable than before.

The objective is not to generate more documentation.

The objective is to build a permanent operating system for creating exceptional brands.

---

# Final Rule

If a decision improves the long-term quality of the repository, choose that decision.

If a decision only improves short-term convenience, reject it.

Long-term consistency always takes priority over short-term speed.

---

**End of AI Rules**
