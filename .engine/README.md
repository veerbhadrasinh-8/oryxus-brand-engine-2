# ENGINE

**Directory:** `.engine`

**Version:** 1.0.0

**Status:** Active

---

# Purpose

The `.engine` directory contains the operational foundation of the Oryxus Brand Engine.

It defines **how the repository is built, maintained, reviewed, and expanded**.

Unlike the documents inside `docs/`, which define branding methodologies, the `.engine` folder defines the rules that govern the repository itself.

Every contributor—human or AI—should understand these documents before creating or modifying repository content.

---

# Why This Directory Exists

As the Brand Engine grows into a large knowledge platform, consistency becomes more important than speed.

Without shared standards:

- Documentation becomes inconsistent.
- Terminology changes.
- Methodologies conflict.
- AI generates different outputs.
- Repository quality decreases.

The `.engine` folder prevents these problems by providing a common operating framework.

---

# Repository Governance

The `.engine` folder governs:

- Repository architecture
- Documentation standards
- AI behavior
- Versioning
- Naming
- Quality assurance
- Completion criteria
- Long-term evolution

No methodology documents should redefine these standards.

---

# Maintenance

The `.engine` directory should remain relatively stable.

Updates should occur only when repository governance changes.

Methodology improvements belong in the `docs/` directory, not in `.engine`, unless they affect repository-wide standards.

---

# Dependencies

Every major document within the Brand Engine depends on the standards established in this directory.

Changes made here may affect:

- Documentation
- Templates
- Frameworks
- Playbooks
- Skills
- Prompts
- Agents
- Future platform development

Repository-wide changes should therefore be made carefully and reviewed thoroughly.

---

# Final Principle

The `.engine` directory is the operating layer of the Oryxus Brand Engine.

It does not teach branding.

It teaches **how the Brand Engine itself should be built, maintained, and evolved**.

Every future contribution should begin here.
