# GLOSSARY

**Document:** Repository Glossary

**Version:** 1.0.0

**Status:** Active

---

# Purpose

The purpose of this glossary is to establish a single, consistent vocabulary for the Oryxus Brand Engine.

Every contributor—human or AI—must use these definitions consistently across the repository.

A term should have **one meaning** throughout the Brand Engine.

If a definition changes, this glossary must be updated before related documentation is revised.

---

# Why a Glossary Exists

As the repository grows into thousands of pages, inconsistent terminology creates:

- Duplicate concepts
- Conflicting documentation
- Miscommunication
- AI hallucination
- Poor maintainability

This glossary eliminates ambiguity.

---

# Terminology Rules

- One concept = One term.
- Never invent synonyms for defined concepts.
- Prefer repository terminology over industry buzzwords.
- New terminology must be added here before widespread use.
- Higher-level definitions override lower-level interpretations.

---

# Core Repository Terms

---

## Brand Engine

The complete knowledge platform developed by Oryxus containing methodologies, frameworks, standards, templates, playbooks, AI skills, prompts, and operational guidance.

The Brand Engine is the complete system.

---

## Constitution

The highest authority within the repository.

It defines philosophy, principles, beliefs, and long-term direction.

Every other document ultimately references the Constitution.

---

## Core System

A comprehensive body of knowledge dedicated to one discipline.

Examples:

- Research
- UX
- UI
- SEO
- Design System

Core Systems teach **how Oryxus performs a discipline**.

---

## Framework

A structured methodology for solving a specific type of problem.

Frameworks explain *how* to apply Core Systems within a defined context.

Example:

Restaurant Framework

Healthcare Framework

Luxury Framework

---

## Template

A reusable deliverable prepared for repeated execution.

Templates accelerate work without replacing methodology.

Examples:

- PRD
- Brand Strategy
- Audit
- Proposal

---

## Playbook

A documented execution process.

Playbooks describe repeatable workflows that consistently produce high-quality outcomes.

Examples:

- Hero Section Design
- Landing Page Design
- Navigation Design

---

## Skill

A specialized AI capability responsible for one discipline.

Examples:

- UX Architect
- Research Expert
- Brand Strategist

A Skill performs focused work.

---

## Prompt

A lightweight instruction used to execute repository knowledge.

Prompts should reference existing methodology.

They should never become the methodology.

---

## Agent

A coordinated workflow combining multiple Skills.

An Agent performs complex tasks that require several specialized capabilities.

---

## Example

A completed implementation demonstrating repository methodology.

Examples serve as learning references rather than primary documentation.

---

# Brand Terms

---

## Brand

The perception created through every interaction between a business and its audience.

A brand is not a logo.

A brand is an experience.

---

## Brand Strategy

The long-term plan defining positioning, differentiation, messaging, and business perception.

Strategy guides design.

---

## Positioning

The deliberate place a brand intends to occupy within the customer's mind relative to competitors.

---

## Value Proposition

The primary reason customers should choose one business over another.

Every value proposition should be:

- Relevant
- Believable
- Distinct
- Valuable

---

## Brand Voice

The consistent personality expressed through written communication.

Voice remains consistent.

Tone may adapt to context.

---

## Brand Identity

The visual representation of the brand.

Examples:

- Logo
- Color
- Typography
- Photography
- Illustration
- Iconography

---

# Experience Terms

---

## User Experience (UX)

The complete experience of interacting with a product or service.

UX includes research, structure, flow, usability, and emotional outcomes.

---

## User Interface (UI)

The visual layer through which users interact with a product.

UI communicates the experience designed by UX.

---

## Information Architecture

The organization and structure of information.

Information Architecture determines where content belongs and how users discover it.

---

## Design System

A reusable collection of design principles, components, tokens, and standards.

Design Systems improve consistency and scalability.

---

## Component

A reusable interface element.

Examples:

- Button
- Card
- Navigation
- Modal
- Input Field

Components should be independent, reusable, and documented.

---

# Development Terms

---

## Frontend System

The documented standards governing implementation.

Includes:

- Code organization
- Performance
- Accessibility
- Responsiveness
- Maintainability

---

## Performance

The efficiency with which a digital experience loads, renders, and responds.

Performance influences both user satisfaction and business outcomes.

---

## Accessibility

Designing products that can be used by people with diverse abilities.

Accessibility is a requirement, not an enhancement.

---

## SEO

The systematic process of improving discoverability through search engines while maintaining high-quality content and technical implementation.

---

# Repository Terms

---

## Source of Truth

The authoritative document defining a concept.

Every concept should have one source of truth.

Duplicate definitions should not exist.

---

## Knowledge Layer

A level within the repository hierarchy.

Examples:

- Constitution
- Core Systems
- Frameworks
- Templates

Each layer serves a distinct purpose.

---

## Version

A numbered release representing the current state of a document or repository.

Versions communicate change.

---

## Milestone

A significant development objective.

Completion of a milestone indicates measurable progress.

---

## Review

A structured evaluation of documentation before approval.

Review focuses on:

- Accuracy
- Clarity
- Consistency
- Completeness
- Practicality

---

## Repository Health

The overall condition of the Brand Engine measured through consistency, documentation quality, progress, and maintainability.

---

# AI Terms

---

## AI Contributor

Any Artificial Intelligence system participating in repository development.

AI contributors follow repository standards.

They do not define them.

---

## Context

The collection of documents an AI should understand before generating new content.

Context determines quality.

---

## Hallucination

Information generated without support from repository documentation or reliable sources.

Hallucinations must never become repository knowledge.

---

## Repository Memory

The accumulated knowledge stored within the Brand Engine.

The repository—not the conversation—is the long-term memory.

---

# Future Additions

As the Brand Engine evolves, this glossary will expand.

New terminology should only be introduced when:

- A genuinely new concept exists.
- Existing terminology is insufficient.
- The term will be reused across multiple documents.

---

# Final Principle

The glossary exists to preserve consistency.

If two contributors use different words to describe the same concept, the glossary should resolve that difference.

If a contributor is uncertain about terminology, this document should always be consulted before writing new documentation.
